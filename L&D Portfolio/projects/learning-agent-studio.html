AI Learning & SME Studio

01 / Diagnose

Identify what makes learning preparation risky.

Evidence: Problem framing and prototype requirements; no operational baseline.

Learning teams work across SME notes, participant questions, draft content and completion records. An AI assistant could help prepare this material, but missing policies, inaccurate claims and incomplete contact records must remain visible.

My portfolio brings together three independent Zapier/Codex workflow prototypes: a source-based FAQ assistant, an SME content studio and a follow-up assistant. The intended audience is HRBPs and people leaders beginning to use AI.

Expected vs current

Design target: source-based answers, aligned draft learning content, explicit missing information and human approval before release.

Current evidence: independent prototypes and fictional scenarios described in my portfolio résumé. No live deployment, verified throughput, measured time saving or production reliability result is established here.

  • Missing or ambiguous SME source: request clarification and label unsupported statements rather than fill gaps with plausible claims.
  • Unclear ownership: retain a named SME or HR reviewer before publishing learning or answering policy questions.
  • Incomplete workflow records: validate recipients, completion state and prior processing before preparing a follow-up.

The response blends a structured input brief, small preparation workflows and a review checkpoint. It does not require automated authority over HR policy or learner capability ratings.

02 / Design

Keep the source and reviewer in the workflow.

Evidence: Source briefs, instructions and review-gate design.

I structured three preparation tasks: answer learning questions from the supplied brief, turn SME notes into draft materials and prepare follow-ups from completion records.

Each workflow must expose missing information. A source-based answer needs a citation; draft content needs an aligned objective and assessment; a follow-up needs a verified record and recipient. A human owner retains the release decision.

04 / Deliver

Coordinate review before release.

Evidence: Proposed supervised handoffs. No live agents or message sending on this site.

In a supervised pilot, I would track the source version, draft, review owner and unresolved exception until the learning owner approves release.

  • SME: approve accuracy and the objective–practice–assessment alignment.
  • Learning owner: confirm intended recipients, permitted tools and the release decision.
  • L&D coordinator: maintain versions, track outstanding reviews and check follow-up records for duplicates.

Live system access and message delivery require organisational approval. The portfolio examples prepare a human decision; they do not send communications.

05 / Evaluate / Improve

Test exceptions before expanding use.

Evidence: Acceptance scenarios and evaluation plan; no verified time-saving or reliability result.

Acceptance scenarios to validate in a future controlled run

Measure source traceability, unsupported-claim handling, review effort and duplicate handling before making any efficiency claim. A dry run with synthetic records comes before any approved live use.

Change the source, instruction or handoff

Capture a reproducible run before proposing live use: input brief, draft package, unsupported-policy question, invitation correction and recorded SME review. Keep the source and one objective–activity–assessment example visible.

Group failures by cause, update the responsible source or instruction, and rerun the failed scenario. Review effort and error handling must be measured before claiming reliability or efficiency.
